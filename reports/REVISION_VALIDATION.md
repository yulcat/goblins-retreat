## 실제 입력과 UI 검사

- seed 8732: PC 마우스와 모바일 터치 모두 18개 추격전, 보상 18회, 10번의 배치, 1,335명 격퇴, 엔딩 도달. 전투 시간 1,313.43초, 최종 내구도 100. 실행 오류 0, 가로·세로 화면 넘침 0. 첫 추격전 직후 내구도는 94다.
- seed 813: 두 입력 모두 15번째 추격전에서 패배. 실패 기록도 보존했다. 모든 시드에서 자동 정책이 이기게 바꾸지 않았다.
- 저장된 대사와 일시정지 복원, 보관/폐기 되돌리기, 보상 선택 취소, 내구도 140의 보조 재시도 검사 통과.
- 대사 59개, 도움말 6쪽, 강화 선택을 포함한 보상 창, 다량의 인벤토리 페이지를 작은 화면에서 검사했다. 화면 밖 버튼과 모달 내부 잘림을 확인하므로 `overflow:hidden`만으로 통과시키지 않는다.
- 단위·전투 시나리오 16개 통과. 기존의 ‘동일 무기에서 지원 기물의 연결만 바꾸면 생존/패배가 갈리는’ 검사도 유지한다.
- 후반 전투의 실제 시뮬레이터 저장 상태를 PC·세로 화면에서 그려 적 무리·발사체·화상·무기·지형의 표시를 검토했다. 같은 seed 8732의 전투 결과(종료 상태·웨이브·시간·내구도·처치·보상)는 Node, 마우스, 터치에서 정확히 일치했다.

전체 플레이 검사는 실제 버튼·포인터 이벤트로 진행한다. 시각 검사는 저장 상태 픽스처를 사용하며 완주 증거로 사용하지 않는다. 전체 플레이 중 사용한 소스에서 이후 바뀐 게임 부분은 짧은 무전의 표시 시간, 리사이즈 시 기물 페이지 갱신, 제목 화면 Escape 예외 처리와 대사 한 줄의 표현이다. 이 경로들은 별도 UI 검사로 확인하며 전투 로직은 같다.

## 난이도 평가

전투 수치를 고정한 뒤 개발용 20개 시드와 겹치지 않는 100개 시드(base 902341, stride 7919)를 세 정책으로 검사했다.

| 자동 정책 | 완주 | 첫 6개 추격전 통과 | 성공한 전투 시간 평균 |
|---|---:|---:|---:|
| 기본 배치 | 60/100 | 100/100 | 1,420초 |
| 조합 고려 | 90/100 | 100/100 | 1,320초 |
| 임의 배치 | 2/100 | 91/100 | 1,706초 |

300회 모두 승리나 패배로 종료했다. 조합 정책의 성공 전투 시간은 1,252~1,431초였다. 평가 후 무기·적·스케줄·보상 수치는 변경하지 않았다. 평가 파일의 fingerprint는 실행 시작 시 content/sim/bot 원문 해시다. 이후 `content.js`에서 보일의 첫 돌격 대사 한 줄만 자연스럽게 고쳤으므로 최종 원문 해시와는 다르지만 전투 데이터·로직은 같다.

초반에 손상을 받아도 기본/조합 정책은 첫 구간을 통과했다. 이는 ‘초반 압박과 회복 가능성’을 확인하는 근거이며 사람의 난이도 평가를 대신하지 않는다. 반복 봇의 승률을 사람의 승률로 해석하지 않는다.

## 시간과 검증 한계

실제 입력 완주의 전투 시간은 약 21분 53초다. 선택·정비·대사 읽기는 플레이어에 따라 더해지며 전체 30분 전후는 목표 분량이다. 대사를 늘려 읽는 시간이 더 필요해졌지만 실제 사람의 체류시간은 아직 측정하지 않았다.

브라우저 검사는 Chrome과 Chrome의 터치·화면 모사다. 실물 iPhone/Android의 발열·배터리·프레임 성능을 측정한 결과는 아니다. 기본 지원 방향은 PC 가로와 모바일 세로다. 아트와 대사는 제작·화면 검토 결과이며 사람의 미적 만족이나 감정적 반응을 자동 검사로 증명하지 않는다.
