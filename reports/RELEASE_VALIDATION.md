# 출시 검증 기록

2026-09-24 · 고블린은 퇴각 중 v0.1

## 확인한 것

- 실제 마우스 입력: seed 813에서 시작 → 보상 18회 → 18개 추격전 → 엔딩. 전투 1,343.5초, 처치 1,320, 내구도 100. 실행 오류와 화면 가로 넘침 없음.
- 실제 터치 입력: 390×844 세로 화면에서 동일한 전체 흐름 완주. 전투 1,347.5초, 처치 1,319, 내구도 88. 배치·회전·보상·대화·최종 화면을 모두 터치로 조작. 이 실행의 seed는 이전 테스트 도구에서 기록하지 않아 정확한 시드 재현 증거로 사용하지 않는다.
- seed 813의 브라우저와 Node 시뮬레이션은 전투 시간·내구도·처치·보상·구간별 결과가 정확히 일치했다.
- 320×640, 390×844, 768×1024, 1280×720에서 가로 넘침 없음. PC 완주 화면은 1440×1000.
- 읽지 않은 대사 새로고침 복원, 저장된 전투의 일시정지 복원, 보관/폐기 되돌리기, 보상 시험 후 원래 후보·보드·난수 상태 복원, 140 내구도 보조 재시도 버튼 확인.
- 단위·전투 시나리오 검사 14개 통과.

실제 UI 검사는 Playwright의 마우스/터치 이벤트를 사용했다. `__rig.snapshot()`은 읽기 전용이다. 완주 검사에서 전투 결과나 인벤토리를 직접 수정하지 않았다. 테스트 시계와 게임의 2배속을 사용했으므로 테스트 실행 벽시계 시간을 사람의 플레이타임으로 해석하지 않는다. 별도 저장 복구 검사는 시뮬레이터가 만든 패배 저장 파일을 사용했다.

## 배치가 결과를 바꾸는가

12번째 추격전에서 동일한 7개 기물, 같은 강화도, 같은 세트 구성, 같은 적을 비교했다. 못총 2개·톱·박격포의 위치를 유지하고 지원 장치 3개만 옮겼다.

- 급탄기와 냉각기가 해당 무기에 인접: 내구도 100으로 구간 통과.
- 지원 장치가 연결되지 않는 가장자리: 엔진 파괴.

`tests/strategy.test.mjs`가 이 반사실 비교를 고정한다. 이는 ‘배치가 전투에 영향을 준다’는 근거이며, 사람이 느끼는 성취감 자체의 측정은 아니다.

## 빌드와 난이도

20개 개발 시드에서 첫 선택 이후 특정 작업반을 선호하되 다른 기물도 허용한 정책:

| 중심 작업반 | 완주 |
|---|---:|
| 철공 | 10/20 |
| 보일러 | 17/20 |
| 전기 | 12/20 |

작업반을 강제로 한 종류만 사용하게 만들지 않았다. 보일러 중심의 포격·감속 조합이 더 안정적이고, 철공은 방향과 보완 기물의 영향을 더 크게 받는다. 작업반 간 성능이 완전히 같다고 주장하지 않는다.

세 정책은 미래 보상에 접근하지 않고 공개된 보드와 기물 정보를 사용한다. 기본 정책도 합법적인 위치를 전부 훑는 탐색을 하므로 ‘초보 사람’과 동등하지 않다. 조합 정책은 지원 효과·공간 비용·강화를 평가하고 주기적으로 재배치한다. 임의 정책은 결정적인 값으로 후보·합법 위치를 선택하는 약한 비교군이다.

100개 후보 검증 시드와 미사용 200개 평가 시드를 각각 세 정책으로 검사한다. 세트·무기·적 수치는 평가를 시작하기 전에 고정했다. 평가 시작 후 전투 수치를 변경하지 않았다. 보조 재시도의 시작 내구도만 실제로 140이 되도록 수정했고, 이는 두 정책 평가 모두에서 호출되지 않는 복구 경로다. 해당 변경은 단위 검사와 실제 버튼 검사로 따로 확인했다. 평가 JSON의 fingerprint는 실행 당시 content/sim/bot 파일의 SHA-256이다.

| 검증 묶음 | 기본 배치 | 조합 고려 | 임의 배치 |
|---|---:|---:|---:|
| 후보 100개 | 74/100 (74.0%) | 89/100 (89.0%) | 2/100 (2.0%) |
| 미사용 200개 | 129/200 (64.5%) | 183/200 (91.5%) | 5/200 (2.5%) |

미사용 시드의 조합 정책 성공 전투 시간: 최소 1273초, 평균 1372초, 최대 1530초. 기본 정책의 첫 구간 통과는 200/200. 총 900회 평가에서 종료되지 않은 실행은 없었다. 이 결과를 확인한 뒤 전투 수치를 다시 조정하지 않았다.

## 30분의 의미

성공한 자동 플레이의 전투 시간과 정비·읽기 시간은 분리한다. 마우스/터치 완주는 약 22분 24초~22분 28초의 전투를 실제 게임 루프로 끝냈다. 보상 선택 18회에 평균 15초, 웨이브 사이 정비 17회에 평균 10초, 주요 대화에 약 1분을 가정하면 전체는 약 30분 45초다.

이 체류시간 가정은 사람의 관찰 자료가 아니다. 익숙한 플레이어가 빠르게 넘기거나 2배속을 쓰면 더 짧고, 모든 배치를 고민하면 길어진다. 30분 안팎의 완결된 분량과 도달 가능한 엔딩은 제공하지만, 실제 첫 플레이의 중앙값이나 재미·감정적 반응을 검증 완료로 표현하지 않는다.

## 캐릭터와 화면

- 리벳은 플레이어의 연결을 인정하고 자신의 설계를 수정한다. 초반 불신에서 후반 확신으로 바뀐다.
- 보일은 인원과 연료를 계속 챙긴다. 구조 장면과 마지막 인원 확인으로 사람을 두고 가지 않겠다는 의지가 드러난다.
- 깃은 군모 장식을 내놓고, 구조를 명령하고, 최후 연설보다 인원 확인을 받아들인다. 마지막에는 대장실 대신 식사를 택한다.
- 구조 장면은 실제 갑판 개방과 연결되고, 최종 갑판에는 생활 공간의 흔적이 나타난다. 초상화는 고글·기관사 모자와 찻잔·군모로 구분한다.
- 8가지 공격 동작과 4가지 지원 장치, 적 실루엣, 사거리/방향/연결선, 고철 요새·궤도·배경·효과를 Canvas로 그린다. 이미지 생성 도구와 외부 이미지 자원은 사용하지 않았다.
- 색·타이포그래피·판넬을 통일했으며, 전투와 선택 화면의 색 대비를 분리했다. 이는 제작 및 화면 검토 결과이며 독립된 사용자 가독성 연구는 아니다.

## 범위와 남은 한계

단일 지도, 3막·18개 추격전, 8종 공격 기물·4종 지원, 최대 3단계 강화, 3개 작업반의 세트 효과, 7종 적, 대사 7장면, 합성 효과음, 자동 저장·재시도·배속을 구현했다. 서버·계정·영구 능력치 성장·외부 분석 수집은 없다.

자동 브라우저 검증은 데스크톱 Chrome과 Chrome의 모바일 터치/화면 모사다. 실물 iPhone Safari·Android 기기의 열·배터리·프레임 성능은 측정하지 않았다. 인간 승률과 실제 체류시간은 미측정이며, 반복 플레이의 장기 유지율을 약속하지 않는다.
